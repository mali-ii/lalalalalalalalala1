# Занятие 1. Границы операционной системы и нефункциональные требования

## 1. Название и концепция

**EduOS** — учебная операционная система с монолитным ядром, написанная на Python 3.10+.
Роль физического носителя, реестра процессов, журнала и хранилища пользователей выполняет SQLite.
Пользователь работает через командную оболочку (User Space), а оболочка обращается к ядру
(Kernel Space) только через системные вызовы `sys_*`. Каждый вызов проверяется по правам
и журналируется.

Основная идея: показать взаимодействие ключевых подсистем ОС (процессы, память, файловая
система, защита) на уровне логики, без работы с реальным «железом».

## 2. Границы системы

### 2.1. Входит в ОС (реализуется)

| Компонент | Что реализуется |
|---|---|
| Ядро | Загрузка, диспетчеризация системных вызовов, перехват исключений |
| Управление процессами | Создание, состояния (new/ready/running/waiting/terminated), завершение, планировщик Round Robin |
| Управление памятью | Учёт выделения и освобождения памяти по процессам, лимит на процесс |
| Файловая система на SQLite | Создание, чтение, запись и удаление файлов; владельцы |
| Пользователи и защита | Вход по логину и паролю, хэши SHA-256, роли `admin` / `user` |
| Журнал | Запись всех системных вызовов в `syscalls_log` |
| Командная оболочка | Цикл ввода команд, справка, вызов `sys_*` |

### 2.2. Не входит в ОС (имитируется или не реализуется)

| Функция | Обоснование |
|---|---|
| Работа с реальным оборудованием | Требует низкоуровневого кода и прав, недоступных в Python в учебной среде |
| Прерывания и драйверы | Заменяются заглушками (таймер, клавиатура, диск, экран); реальные драйверы требуют знания аппаратуры |
| Реальная виртуальная память (MMU, страничные таблицы) | Аппаратная функция процессора; в учебной ОС ведётся только учёт памяти |
| Сетевые протоколы | Отдельная большая подсистема, не укладывается в отведённое время |
| Интеграция с каталогами (LDAP/AD) | Внешние службы, не нужны для целей работы |
| Графический интерфейс | Не является темой проекта, достаточно текстовой оболочки |
| Многопоточность на уровне ядра | Процессы имитируются записями в БД; реальные потоки усложнят отладку и блокировки SQLite |

## 3. Роли и сценарии использования

**Роли:** *Пользователь* (работа только со своими файлами), *Администратор* (полные права,
управление пользователями), *Система* (фоновые процессы: планировщик, сборщик мусора).

| № | Сценарий | Актёр | Системные вызовы | Модули |
|---|---|---|---|---|
| 1 | Вход в систему | Пользователь | `sys_login` | shell, kernel, auth, db (`users`) |
| 2 | Создание файла | Пользователь | `sys_create` | shell, kernel, fs, db (`files`, `syscalls_log`) |
| 3 | Чтение файла | Пользователь | `sys_open`, `sys_read` | shell, kernel, fs, db |
| 4 | Запись в файл | Пользователь | `sys_open`, `sys_write` | shell, kernel, fs, db |
| 5 | Запуск процесса | Пользователь | `sys_exec` | shell, kernel, process, memory, scheduler, db (`processes`) |
| 6 | Просмотр списка процессов | Пользователь | `sys_ps` | shell, kernel, process, db |
| 7 | Завершение процесса | Пользователь / Админ | `sys_kill` | shell, kernel, process, memory, db |
| 8 | Выделение памяти | Пользователь | `sys_alloc` | shell, kernel, memory, db |
| 9 | Просмотр журнала вызовов | Администратор | `sys_get_log` | shell, kernel, db (`syscalls_log`) |
| 10 | Создание пользователя | Администратор | `sys_add_user` | shell, kernel, auth, db (`users`) |
| 11 | Планирование процессов | Система | внутренний `schedule_tick` | scheduler, process, db |
| 12 | Завершение работы ОС | Администратор | `sys_shutdown` | shell, kernel, db |

**Пример (сценарий 1).** Пользователь вводит логин и пароль → оболочка вызывает `sys_login` →
ядро передаёт запрос модулю аутентификации → модуль читает хэш из `users` и сравнивает с SHA-256
введённого пароля → при совпадении ядро устанавливает текущего пользователя → вызов пишется
в `syscalls_log`.

## 4. Нефункциональные требования

### 4.1. Производительность
| ID | Требование | Метрика | Способ проверки |
|---|---|---|---|
| P-1 | Время обработки одного системного вызова | ≤ 50 мс | `time.perf_counter()` в декораторе `syscall` |
| P-2 | Одновременно поддерживаемые процессы | ≥ 10 | Тест: запуск 10 процессов подряд |
| P-3 | Запуск ОС и инициализация БД | ≤ 1 с | Замер `boot()` |
| P-4 | Кванты планировщика | 1 квант = 100 мс, задержка переключения ≤ 10 мс | Логи планировщика |

### 4.2. Надёжность
| ID | Требование | Метрика | Проверка |
|---|---|---|---|
| R-1 | Ошибка в пользовательском процессе не роняет ядро | 0 аварийных завершений ядра при 100 ошибочных вызовах | Тест с исключениями |
| R-2 | Ошибочный процесс останавливается, ошибка пишется в журнал | 100 % ошибок в `syscalls_log` со статусом `error` | Проверка таблицы |
| R-3 | Превышение лимита памяти (1024 КБ) отклоняется с кодом ошибки | Процесс не получает память сверх лимита | Тест `sys_alloc` |
| R-4 | Целостность БД при сбое | Операции записи выполняются в транзакциях | Прерывание записи, проверка БД |

### 4.3. Безопасность
| ID | Требование | Метрика | Проверка |
|---|---|---|---|
| S-1 | Пароли хранятся только как SHA-256 | 0 паролей в открытом виде в `users` | Просмотр таблицы |
| S-2 | Пользователь не изменяет и не удаляет файлы администратора | 100 % таких попыток отклоняются | Тесты прав |
| S-3 | Журналируются все вызовы: имя, аргументы, пользователь, результат | 100 % вызовов имеют запись | Сравнение числа вызовов и записей |
| S-4 | Привилегированные вызовы только для `admin` | `sys_add_user`, `sys_get_log` недоступны роли `user` | Тесты ролей |
| S-5 | Защита от SQL-инъекций | Только параметризованные запросы | Ревью кода |

### 4.4. Поддерживаемость
| ID | Требование | Метрика | Проверка |
|---|---|---|---|
| M-1 | Модульность: один модуль — одна задача | Модуль ≤ 300 строк | `wc -l src/*.py` |
| M-2 | Документирование | Docstring у каждого модуля и публичной функции | Ревью |
| M-3 | Автотесты | ≥ 1 тест на каждый системный вызов | `unittest discover` |

### 4.5. Ресурсоёмкость
| ID | Требование | Метрика | Проверка |
|---|---|---|---|
| E-1 | Только стандартная библиотека Python 3.10+ | 0 внешних зависимостей | Отсутствие `requirements.txt` |
| E-2 | Без внешних СУБД и серверов | Только встроенный `sqlite3` | Запуск на чистой машине |
| E-3 | Размер файла БД после типового сеанса | ≤ 10 МБ | Размер `db/os.sqlite` |

## 5. Анализ рисков

| № | Риск | Вероятность | Влияние | Стратегия минимизации |
|---|---|---|---|---|
| 1 | Нехватка времени | Высокая | Высокое | Приоритизация: ядро и БД → ФС и оболочка → доп. функции |
| 2 | Блокировки SQLite при частых обращениях | Средняя | Среднее | Одно соединение и очередь запросов; короткие транзакции |
| 3 | Сложность отладки системных вызовов | Средняя | Среднее | Сквозное логирование всех вызовов с параметрами и результатом |
| 4 | Забытая обработка ошибок | Средняя | Высокое | Чек-лист; декоратор `syscall` перехватывает исключения |
| 5 | Потеря целостного представления о проекте | Средняя | Среднее | Ведение документации, регулярная сверка с ней |
| 6 | Пароли в открытом виде по ошибке | Низкая | Высокое | Единая функция `hash_password`, тест на длину хэша |
| 7 | Излишнее усложнение планировщика | Средняя | Среднее | Только Round Robin; другие алгоритмы — по остаточному времени |
| 8 | Потеря кода | Низкая | Высокое | Частые коммиты, удалённый репозиторий |

## 6. Описание прототипа

| Модуль | Назначение | Как проверить |
|---|---|---|
| `src/config.py` | Пути, лимиты, версия | Импорт без ошибок |
| `src/db.py` | Соединение, создание 4 таблиц, администратор по умолчанию, `hash_password` | `python src/db.py` → файл `db/os.sqlite`, 4 таблицы в SQLite Viewer |
| `src/syscalls.py` | Декоратор `syscall` (лог, замер времени, перехват ошибок), `sys_echo`, `sys_get_users` | Записи в `syscalls_log` |
| `src/kernel.py` | Загрузка ОС (`boot`) | Запуск оболочки |
| `src/shell.py` | Баннер, команды `help`, `echo`, `users`, `exit` | `python -m src.shell` |
| `tests/test_prototype.py` | Автотесты | `python -m unittest discover tests` |

Порядок проверки: `python src/db.py` → `python -m src.shell` → выполнить `help`, `echo привет`,
`users`, `exit` → открыть `db/os.sqlite` и убедиться, что в `syscalls_log` есть записи
`sys_echo` и `sys_get_users`.

## 7. Словарь терминов

| Термин | Определение |
|---|---|
| Ядро | Постоянно находящаяся в памяти часть ОС, управляющая всеми ресурсами и обрабатывающая запросы программ |
| Пространство ядра (Kernel Space) | Защищённая область памяти, доступная только модулям ядра |
| Пространство пользователя (User Space) | Область, где работают прикладные программы и оболочка без прямого доступа к ресурсам |
| Системный вызов | Формализованный интерфейс, через который программа просит ядро выполнить привилегированную операцию |
| Процесс | Программа в момент выполнения, со своим состоянием, памятью и открытыми файлами |
| Поток | Лёгкая единица выполнения внутри процесса, разделяющая с другими потоками адресное пространство |
| Дескриптор | Числовой идентификатор открытого файла, через который выполняются чтение и запись |
| Планировщик | Модуль ядра, выбирающий, какой процесс получит процессор |
| Виртуальная память | Механизм, при котором адреса процесса отличаются от физических и транслируются ядром |
| Страница | Блок фиксированного размера — минимальная единица выделения памяти |
| Хэширование | Необратимое преобразование данных в строку фиксированной длины (например, SHA-256) |
| Аутентификация | Проверка подлинности пользователя (логин и пароль) |
| Авторизация | Определение действий, разрешённых аутентифицированному пользователю |
| Монолитное ядро | Архитектура, где все подсистемы работают в едином адресном пространстве ядра |
| Драйвер | Программа, обеспечивающая взаимодействие ядра с устройством (в EduOS — заглушка) |
